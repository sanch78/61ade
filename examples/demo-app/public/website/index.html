01The idea

Build the application.
Start with the essentials in place.

Sign-in, permissions, forms and lists come up in almost every project. 61ade gives them a common foundation, so they work together instead of being rebuilt one screen at a time.

Declare the everyday.

Describe resources, fields, views and actions in PHP or modular JSON. The toolkit turns those definitions into a working admin interface.

Extend where it matters.

Use your own PHP handlers and TypeScript modules for your application’s behavior. The public toolkit provides components, services and extension points.

Keep your domain yours.

Your business logic, data and integrations belong to your project. 61ade supplies the shared admin infrastructure underneath.

03Foundations

And the foundations
behind the screens.

The parts nobody sees until they are missing. They are built in, and every new capability takes part in them.

Sign-in & users

Password sign-in, optional e-mail verification, remembered sessions and user administration. An optional AuthHandler integration provides external sign-in; provider setup is required.

Documentation↗

Permissions & administration

Roles, object and field permissions, and scoped API keys. Access is checked on the server, through the same action executor used by the interface.

Documentation↗

Lists & forms

Filtering, sorting, inline editing, validation, record details and related views. Lists adapt to cards on smaller screens; the desktop file manager and diagram editor have their own size requirements.

Documentation↗

API, audit & live data

Registered actions can be exposed through scoped API keys. An audit journal records supported operations. Lists support polling or a configured WebSocket service; a searchable log administration screen is still planned.

Documentation↗

Project modules & components

Build your own views, field types and commands with the public TypeScript toolkit. Reuse list, form, file, calendar, diagram and media components; run untrusted project content in the sandbox component.

Documentation↗

Languages, themes & tenants

Built-in localization, light and dark themes, application skins and optional multi-tenancy for SQL resources. Tenant-scoped file storage is not yet implemented.

Documentation↗

Actively evolving. PHP is the current backend; SQLite powers the demo. A language-independent backend contract, PostgreSQL and JSON-file storage remain future work.

04The story

Experience first.
Tools evolve.

61ade is a new toolkit with a much longer story behind it.

  1. DDE

    The HTML4 years

    Before ADE, there was DDE: an HTML4-based framework that proved useful at around twenty customers.

  2. ADE

    One developer. Real projects.

    ADE was already the third framework I had built in my life. I made it entirely on my own, starting when AJAX was still a fashionable new term. Its AJAX-based, HTML5-ish hybrid interface served many projects for banks, telecom companies and systems integrators.

  3. 61ade

    Experience meets AI.

    I know from hands-on work what makes a useful HTML5 admin interface with a PHP backend. This time, the toolkit was built with AI, under my active direction and grounded in the experience and lessons of those earlier systems.

— sanch, creator of 61ade
