# Accepted grid, tree, and card rules

This ledger keeps the skill tied to observed 61ade decisions without turning
feedback history into a second implementation guide. Read it when a task
touches one of these rules; read the linked topic guide for the full public
contract and current limitations.

| Evidence | Reusable lesson | Current scope or limit |
| --- | --- | --- |
| [FB-0006](../../../../docs/feedback.md#fb-0006--konfigurálható-munkaterület-dinamikus-és-élő-listák) | A workspace is a validated layout tree with separate filter/results and optional panel form; list data is authorized, bounded, cursor-based, and live updates share the same window. | 61ade Standard Grid uses public APIs because PRO LazyDataProxy is unavailable. |
| [FB-0013](../../../../docs/feedback.md#fb-0013--a-panelméretező-középre-igazítása) and [FB-0015](../../../../docs/feedback.md#fb-0015--fölösleges-keretezett-layoutburkoló) | Keep the native layout root, one outer frame, and native resizers; do not repair spacing by moving widgets or adding wrapper frames. | Suite 9.3.12 gap/grip behavior is version-sensitive; the framework centres the grip of both `space` and `wide` layouts (FB-0058). |

| [FB-0055](../../../../docs/feedback.md#fb-0055--egyedi-muveleti-parancsok-es-ikonok) | Keep one command per action with its original label/icon; a marked-row execution reuses the bulk-capable action instead of adding a selected-rows command. | Field-free actions execute directly; input actions use one form. |
| [FB-0058](../../../../docs/feedback.md#fb-0058) | A hierarchy browser may offer, per panel, either the listing or the tree as a selectable view mode (mc style); the tree selection is that panel's current folder and the mode switch keeps folder and marks. | File manager panels; the Tree adapter loads a mount's directories at once. |

| [FB-0058](../../../../docs/feedback.md#fb-0058) | A data tree that browses records shows leaves too, with the same type icon as the listing, and a chosen leaf is the operand; an alternate listing/tree surface that must keep widget listeners is hidden by cell CSS rather than a Layout `views` switch, which re-creates the widget DOM. Icons are a framework `icon` column with a localized accessible name, never the only meaning. | File manager scope; tree bounded to 2000 directories and 5000 files per mount. |
| [FB-0024](../../../../docs/feedback.md#fb-0024--kártyaszerkesztés-mentés-utáni-nézetváltás-méret-és-rendezés) and [FB-0058](../../../../docs/feedback.md#fb-0058) | Every content window is sized by the shared `fitWindow`; extra height (viewport cap or manual enlargement) goes to a Form textarea, never to an empty band below the actions. No fixed pixel control height in a window larger than its content. | Windows whose Form has a direct textarea cell; forms without one keep the fitted height and native scrolling. |
| [FB-0058](../../../../docs/feedback.md#fb-0058) | A document (text, image, video) opens in a document window: a full-window Layout with a native Toolbar row (Save + Ctrl+S when editable, view commands, state text) above a content cell that fills the window; the window's close is the cancel, with an unsaved-changes confirmation. Binary content reaches the browser as a framework `Download` action result shown through a blob URL, never base64 JSON. | File manager: `.txt` editor, PNG/JPEG viewer, MP4/WebM player; forms and details keep `fitWindow`. |
| [FB-0058](../../../../docs/feedback.md#fb-0058) | Navigation to a parent in a hierarchical listing is a first `..` row marked `_markable: false` (cursor only, never a mark or operand), not a separate Up command; returning puts the cursor on the child just left. A location shown in a panel header is collapsed in the middle, keeping its root and last segment, with the full value in the native tooltip. | File manager listing; the tree navigates by its own nodes. |
| [FB-0071](../../../../docs/feedback.md#fb-0071) | An expandable row or card is a compact look: the related records in a table with sortable headers only (plus declared editable switches), height fitted to 5–10 rows by the viewport before it scrolls, the same in cards and on a phone. All work happens in the full list, opened in a window from the parent toolbar; never a full view nested in a row or card. | `Registry::subview()`; tiles do not expand; a preview does not expand further. A child list where only a flag is set (tenant access) is not selectable (`select: false`): no highlight, cursor, delegation or form, the switch only. |
| [FB-0071](../../../../docs/feedback.md#fb-0071) | A window that holds one framework feature shows it edge to edge, with the window header as its only header (no inner panel header, margin or frame). | `blade-feature-window`; forms keep `fitWindow`. |
| [FB-0071](../../../../docs/feedback.md#fb-0071) | A widget nested in a row or card must not live inside the host Grid/DataView DOM, or the host's mouse and key handling captures it: reserve a slot and place the nested widget in a clipped overlay layer that follows it. | Standard edition; the native Grid `subRow` is PRO-only. |
| [FB-0077](../../../../docs/feedback.md#fb-0077) | What double-click and Enter run on a record is declared view metadata naming a command the view already has (details, the sub-view window, a record action) and runs as that toolbar command does, the same in table, cards and tiles; an unoffered activation falls back to the details. Custom server behavior is a registered action handler; custom browser behavior is a record view of a registered view kind ([FB-0081](../../../../docs/feedback.md#fb-0081)), never a callback in the declaration. | `view.activate`; cards/tiles carry an `aria-description` of the target; a window opened by activation takes the focus. [FB-0078](../../../../docs/feedback.md#fb-0078): a drill-down to a child list that has its own page navigates to that page with an ordinary, removable filter instead of nesting it (`page`). |
| [FB-0079](../../../../docs/feedback.md#fb-0079) | A menu page's filter values are a per-user, browser-local preference like sort and mode; restoration revalidates them against the actor's current filter definitions and drops stale values, and the active filter stays visible (header, panel, count) and removable. | Not the search text, sub-view previews/windows or singletons; no device sync. |
| [FB-0081](../../../../docs/feedback.md#fb-0081) | Project code composes the framework list component in its own layout; a layout cell holds either markup or widgets, alternating content gets a fresh layout per content; a composed list's saved state follows the view identity it is given; marks and the cursor row are transient; a custom column presentation escapes values and carries a text alternative. | Public contract and pitfalls: [toolkit](../../../../docs/toolkit.md#layout-recipe). |

## Known boundaries

- The current Tree adapter handles a flat parent list and the file manager. Lazy
  children, drag/move, and large-tree virtualization are demand-driven work;
  treat them as contracts to design and qualify, not as existing guarantees.
- The exact current card target is approximately 340 px columns, one column on
  mobile; the exact list window is bounded (100-row browser chunks and up to 600
  retained rows in the current workspace). Choose and document different limits
  only when the owning adapter and tests support them.
- Public behavior and limitations belong in [workspaces](../../../../docs/workspaces.md),
  [usage](../../../../docs/usage.md), and the affected topic guide. This ledger is
  a routing map for the skill, not a replacement for those documents.
