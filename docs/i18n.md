# Többnyelvűség

A nyelvi infrastruktúra minden VAPA-alkalmazás része. A választó opcionális;
egyetlen nyelven használt site is ugyanazon fordítási útvonalon működik.
A keret magyar, angol és német katalógust ad a saját felirataihoz,
validációihoz, futási hibaüzeneteihez és belépést megerősítő leveleihez.
A fogyasztó saját üzleti fordításokat ad meg, a keretbe üzleti szöveg nem kerül.

## Konfiguráció

A gyökér alkalmazás-JSON opcionális `i18n` szekciója:

```json
{
  "i18n": {
    "default": "hu",
    "languages": {"hu": "Magyar", "en": "English", "de": "Deutsch"},
    "selector": true,
    "catalogues": {"hu": "locales/hu.json", "en": "locales/en.json", "de": "locales/de.json"}
  }
}
```

Az útvonalak az alkalmazás-JSON könyvtárához képest értendők. A katalógus
lapos JSON objektum: stabil üzenetkulcs → fordítás. A meglévő deklarációk
forrásszövege is üzenetkulcs; így a címkék átvezetése nem változtatja meg
a mező-, művelet- vagy objektumazonosítókat. Példa angol katalógusra:

```json
{"Szintetikus elemek": "Synthetic items", "Üzleti címke": "Business label"}
```

Közvetlen PHP-fogyasztó `ApplicationDefinition(languages: new
Vapa\I18n\Settings(...))` formában konfigurálhat; deklaráció beolvasásához
`LanguageConfiguration::build($definition, $pathResolver)` használható.
Szekció nélkül: `hu`, Magyar, rejtett választó. Angol, választó nélküli site:
`default: en`, `languages: {en: English}`, `selector: false`. A default nyelvnek
szerepelnie kell a támogatott nyelvek között. Nyelvkód: `hu`, `en`, `de`,
vagy szabályos `xx-YY`; további nyelvhez a keretfeliratokat is a fogyasztó
katalógusában kell megadni. Egyetlen nyelvnél a választó mindig rejtett.

## Nyelvválasztás és hatókör

A natív DHTMLX Toolbar nyelvválasztó a skinválasztó elé kerül; mobilon is
látható. A belépési/megerősítési modalon belül natív Form select biztosítja
az elérést a modal fókuszhatárán belül. Az elemek saját nyelvükön jelennek
meg: Magyar / English / Deutsch. A választás CSRF-védett POST a keretben;
nem támogatott nyelv és hibás token nem módosítja a preferenciát.

A választás `${sessionName}_language` nevű, HttpOnly, SameSite=Lax,
HTTPS-en Secure cookie-ban egy évig, a site cookie-útvonalán marad meg.
Belépés és kijelentkezés nem törli. Ez böngészőpreferencia, nem jogosultság
vagy felhasználói profiladat. A váltás teljes újratöltés, megtartott URL-hash-sel;
a nyitott form el nem mentett értékei nem kerülnek át az új nyelvű oldalra.
A rendezés, nézet és layout meglévő preferenciái stabil azonosítókhoz kötöttek.

A HTML `lang`, HTTP `Content-Language`, kliens bootstrap és a szerveroldali
fordító ugyanazt a locale-t használja. Bearer API-n az opcionális
`X-VAPA-Locale` fejléc választ a site támogatott nyelvei közül; ismeretlen
érték a default nyelvre esik vissza. Közvetlen CLI/API-használó explicit
`Translator::configure($settings, $locale)` hívással állít kontextust.
Konfiguráció/DB betöltése előtti általános kiesési oldal a keret magyar
fallbackját használhatja; belépést vagy SMTP-levélkézbesítést ez nem igazol.

## Fordítási szerződés

PHP-n `Translator::text($key, $parameters)`, TypeScriptben `t(key, parameters)`
old fel. A `{count}`, `{name}`, `{minutes}` paraméterek neve megmarad;
a megjelenítési útvonal a szokásos HTML-escape-et alkalmazza. A feloldás
sorrendje: választott nyelv fogyasztói/keretkatalógusa, default nyelv
fogyasztói/keretkatalógusa, eredeti kulcs. A fogyasztó felülírhat keretszöveget.
Új feliratot csak a közös fordítóval és az összes érintett katalógus
frissítésével szabad bevezetni.

A fordítás célzottan a prezentációra vonatkozik: menük, műveletek, mezők,
oszlopok, layoutfejlécek, validációs üzenetek, statikus választóopciók és levelek.
A rekordadatok, jelszavak, azonosítók, alapértékek, SQL és adatbázisból jövő
lookupfeliratok nem fordulnak át. A dinamikus üzleti opciókezelő a saját
ismert feliratait `Translator::text`-tel adja vissza. A számkijelzés a választott
locale-t követi. A használt Suite komponensek elérhető natív message/grid/
form/combobox/window/toolbar locale-jait a közös frontend adapter állítja;
a Suite által nem lokalizálható technikai vezérlőnevek megmaradhatnak angolul.
A felületi nyelv nem jelent automatikus tartalom- vagy adatbázisfordítást.

## Ellenőrzés

- `php8.4 tests/shell/i18n.php`: fallback, paraméterek, validáció, statikus
  opciók, rekordértékek változatlansága, levél-render és katalógusparitás.
- Védett `npm run test:browser -- --config playwright.i18n.config.cjs`:
  önálló szintetikus fogyasztó három nyelvvel, modalon belüli váltás,
  szerveres belépési hiba, frontend validáció, mobil és rejtett választó.
- A fogyasztó a saját definícióinak, üzleti hibáinak és leveleinek fordítását
  külön teszteli. A renderpróba nem küld valódi e-mailt.
